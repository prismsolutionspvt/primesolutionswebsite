# Database

All SQL lives in `supabase/migrations/` (run in file-name order) plus `supabase/seed.sql`. Nothing is changed by hand in the dashboard. To change the schema, add a **new** migration file; never edit one that has already been applied.

| File | Contents |
| --- | --- |
| `…0100_core_auth.sql` | Validated domains (`media_path`, `safe_url`), `touch_updated_at()`, **`owner_lock`** + **`is_owner()`**, `current_admin_role()`, `activity_log` + trigger |
| `…0200_content.sql` | All website content tables, RLS, `reorder_rows()` |
| `…0300_enquiries_media.sql` | `enquiries`, `enquiry_notes`, `media_assets`, the flood-guard trigger, RLS |
| `…0400_storage.sql` | `site-media` bucket and storage policies |
| `…0500_owner_bootstrap.sql` | Inserts the owner address (edit before running to hand over) |
| `seed.sql` | Starter content from `src/content` (idempotent; generated by `npm run db:seed:generate`) |

## Tables

Collections share: `id uuid`, `sort_order`, `is_published`, `created_at`, `updated_at`.

| Table | Purpose |
| --- | --- |
| `owner_lock` | One row, one address. No API access at all. |
| `site_settings` | One row: company, SEO, contact, WhatsApp, Instagram, brand images, footer, "Powered by" credit, theme, `content_seeded` |
| `site_sections` | Heading/intro copy per public section (`hero, about, values, services, why, industries, approach, team, reviews, faq, contact, commitment`) + `is_visible`; section-specific values live in `extra` (jsonb) |
| `mission_vision` | One row: mission and vision text, highlights, images |
| `services`, `service_subcategories` | Services (slug, group heading, icon, image, descriptions) and their items (child rows, cascade delete) |
| `industries` | Industry, description, compliance note, `fits` (service slugs), illustration, image |
| `team_members` | Name, designation, bio, extra info, photo |
| `core_values`, `why_prism_items`, `approach_steps` | Ordered lists. `core_values.is_principle` marks Quality / Commitment / Performance |
| `faqs` | Question, answer, topic (topics become the filter chips) |
| `testimonials` | **Owner testimonials and visitor reviews**, one moderated table: `source` (owner/visitor), `status` (pending/published/rejected), `rating`, `is_featured`, `client_token` (idempotency) |
| `announcements` | Title, texts, image, button, schedule, priority, frequency rules |
| `social_links` | Extra social profiles (Instagram has its own setting) |
| `enquiries`, `enquiry_notes` | Contact-form submissions (status new / contacted / in_progress / converted / closed) and internal notes |
| `media_assets` | Register of every uploaded file (path, type, size, alt text) |
| `activity_log` | Written by triggers; powers "Recent content updates" |

Indexes cover ordering columns, `testimonials(status, created_at)`, `enquiries(created_at)` and `(status, created_at)`, `activity_log(at)`, `media_assets(created_at)`.

## Access rules (Row Level Security on every table)

| Who | May |
| --- | --- |
| Visitor (`anon`) | read **published** rows only (announcements: enabled and not expired; subcategories: only if the parent service is published); `INSERT` a review (forced `pending`/`visitor`, rating 1–5, no photo, not featured) and an enquiry (forced `new`); nothing else |
| Any signed-in non-owner | exactly the same as a visitor (the e-mail link is only ever sent to the owner, and the database ignores everyone else) |
| Owner | everything, through the app (the owner's own session; no service key) |

## Constraints worth knowing

- Text columns have length caps; URLs must be `http(s)`, a site-relative path, `#anchor`, `mailto:` or `tel:` (`safe_url`, so `javascript:` can never be stored); image paths must be plain paths inside the bucket (`media_path`, no `..`).
- `announcements`: `ends_at > starts_at`. `enquiries.email`, phone, message length are checked.
- `throttle_public_inserts()` limits non-owner inserts: 40 enquiries and 30 visitor reviews per 10 minutes (global). It stops scripted flooding of the public key without blocking the owner.
- Deleting a service deletes its subcategories; industries refer to services by slug, and dangling slugs are ignored when rendering.

## Adding a field or table

1. New migration `supabase/migrations/<timestamp>_<name>.sql` (add the column with a `CHECK`, keep RLS enabled, grant explicitly).
2. If it is managed in the admin: add the field to the right entry in `src/admin/registry.ts`.
3. If it is public: map it in `src/lib/content/map.ts`, add it to the type in `src/types/content.ts` / `src/lib/content/types.ts`, use it in the component.
4. Add a case to `supabase/tests/rls.test.mjs` and run `npm run db:test`.
